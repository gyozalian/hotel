- Do NOT define new CSS variables. Do NOT write hex colors, rgb() or font sizes in the page.
  Use only var(--md-*), var(--ch-*), var(--st-*), var(--warn*), var(--sp-*), the .t-* type classes,

  .chip, .tag, .list, .table, .field, .banner, .segmented, .avatar, .icon, .progress, .divider).

- Every card is <article class="card card--outlined"> (a white tile). Never put a card inside a card.
  For a tinted box inside a card use a <div> with background: var(--md-surface-container-low)
  and border-radius: var(--md-shape-sm).
- Buttons always need two classes: class="btn btn--filled" (or --tonal/--outlined/--text).
- Put the page sections inside <div class="stack"> with
  `.stack { display: grid; gap: var(--layout-gutter); }` so they never touch.
- Every page grid you define needs `grid-template-columns: minmax(0, 1fr)` for the one-column (phone)
  case, and minmax(0, …) for its columns, otherwise a table or timeline stretches the page on phones.
- Elements inside a card need a layout class (flex column + gap var(--sp-3)), otherwise
  they run together on one line.
- A page-specific <style> block is allowed ONLY for layout (grid, flex, gap, widths, position)
  and must stay under about 70 lines.
- Use EXACTLY the data given in the page brief. Do not invent other guests, prices or dates.
- Copy the <script> from the end of dashboard.html (chips, segmented buttons, scrolled top bar).
- Before writing, list the sections of the page and which component each one uses.
  Then write the file in one go.
- When done, say which parts you are unsure about. Do not write a validation report and do
  not claim everything is correct: a person will check it in a browser.
